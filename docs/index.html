Clinical Operational Context

The Challenge of Modern Outpatient Operations

Healthcare facilities often battle fragmented schedules, telephone bottlenecks, and data silos that degrade patient satisfaction and exhaust medical staff.

Traditional Clinic Bottlenecks

Manual appointment coordination and disparate physical registries cause severe clinical overhead:

  • Opaque Availability: Patients cannot view real-time physician schedules across hospital branches.
  • High No-Show & Collision Rates: Simultaneous booking requests lead to accidental duplicate bookings and empty time slots.
  • Fragmented Medical Records: Consultations occur without immediate, consolidated access to patient diagnostic attachments.
  • Administrative Fatigue: Hospital staff spend critical hours reconciling doctor calendars and managing paper queues.

The NexClinic Digital Standard

An integrated, multi-tenant outpatient operating system engineered for clinical precision:

  • Real-Time Doctor Discovery: Comprehensive directory with filtering by medical specialization, hospital branch, and live slot status.
  • Concurrency-Safe Booking: DB-level transactional locking guarantees that slots cannot be double-booked during concurrent requests.
  • Secure Document Lifecycle: Patients securely upload diagnostic files and prescriptions via validated multipart form pipelines.
  • Automated Shift Generation: Celery workers automate 14-day rolling appointment availability based on hospital slot templates.

Interface Design & UX

Authentic Product Experience

Real interfaces built with Next.js App Router and Tailwind CSS, prioritizing clarity, trust, and zero cognitive load.

01 / SECURE ACCESS

Unified Authentication & Two-Factor OTP

A single, secure login gateway serving Patients, Doctors, and Administrators. After credential validation, the system enforces email-gated 6-digit OTP verification. Tokens are delivered strictly via HttpOnly, Secure cookies to prevent XSS session hijacking.

  • Temporary `PendingUser` holding state prevents unverified database bloat.
  • Rate-limited OTP dispatch via SendGrid / SMTP with live cooldown timers.

02 / PATIENT PORTAL

Optimistic Booking & Practice Management

Patients experience instant, zero-lag interface responses. When a slot is selected, the client-side state reflects the reservation immediately while a background database transaction verifies capacity using row-level locking.

  • Instant feedback with standardized toast notifications for edge cases.
  • Seamless role-specific redirects managed by Next.js Edge Middleware.

Dual-Engine Routing

HTTP REST traffic (`/api/*`) is directed through standard WSGI workers for relational business operations, while WebSocket streams (`/ws/*`) route directly to ASGI Daphne servers, isolating long-lived chat connections from request pools.

Asynchronous Slot Generation

Instead of calculating slot intervals on the fly, Celery Beat runs scheduled routines reading hospital `SlotTemplates` to physically stamp out rolling 14-day booking records in PostgreSQL, keeping query response times below 30ms.

Stateless Edge Token Validation

The Next.js Edge proxy decrypts JWTs in memory to reject unauthorized cross-role attempts with a 307 redirect before reaching the origin Django server, dramatically decreasing server workload.

Security & Data Integrity

Built-in Defense & Concurrency Protection

Healthcare platforms demand strict confidentiality and faultless operational integrity. NexClinic guarantees data security across layers.

HttpOnly JWT Cookie Pipeline

Authentication tokens (access and refresh) are written to client browsers strictly via `Set-Cookie` with HttpOnly, Secure, and SameSite=Lax attributes. Client-side JavaScript cannot access the tokens, completely mitigating Cross-Site Scripting (XSS) session theft.

Set-Cookie: access_token=***; HttpOnly; Secure; SameSite=Lax; Path=/

Pessimistic Concurrency Locking

To prevent race conditions during peak booking periods, appointment creation uses PostgreSQL row-level locks (select_for_update). Concurrent booking requests are queued deterministically at the database engine level.

slot = AppointmentAvailableSlot.objects.select_for_update().get(id=slot_id)

Two-Tier RBAC Verification

Role boundaries are verified twice: first at the Next.js edge router (`src/proxy.ts`), and definitively inside Django via granular permission classes (IsPatient, IsDoctor, IsHospitalAdmin).

permission_classes = [IsAuthenticated, IsDoctor]

Cross-Browser E2E Quality Assurance

Crucial clinical user journeys are continuously validated using an automated Playwright test suite spanning Desktop Chromium, Microsoft Edge, and Mobile Chrome profiles to guard against UX regressions.

npx playwright test --project=chromium,edge,mobile-chrome
